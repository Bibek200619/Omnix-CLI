Use two project-level Vercel routing rules on `omnix`, restricted to the host
`www.omni-x.co.in`: exact `/cli` → `https://omnix-cli-website.vercel.app/cli`,
and source `/cli/:path*` → destination `https://omnix-cli-website.vercel.app/cli/:path`.
The destination must omit the source's `*` modifier: this routing API substitutes
the parameter name but preserves a destination `*` literally, causing asset 404s.
This implements the existing path
contract without redeploying the parent application's unrelated code. Publish
only these rules after inspecting the staged diff. Preserve the domain redirect,
parent routes and DNS. Rollback disables only these two rules and publishes that
change; keep the prior parent deployment unchanged. Record live checks below
after publication. The two rules were published; a scoped Cloudflare prefix purge
for `www.omni-x.co.in/cli/` removed cached asset 404s after the destination repair.

Both rules append `Cache-Control: no-transform` to the origin's cache policy.
Cloudflare's automatic Web Analytics beacon otherwise injects a remote script
that the CLI's existing self-only CSP correctly blocks. This header prevents
payload modification for the CLI zone, preserving its reviewed HTML and caching
directives without relaxing CSP or changing the parent site's analytics settings.
See [Cloudflare's automatic setup documentation](https://developers.cloudflare.com/web-analytics/get-started/).

stable production project origin, add these two
rewrites to the existing frontend's reviewed configuration, before its fallback

```text

/cli/:path*   -> CLI_ORIGIN/cli/:path*
```

it must not contradict noindex metadata/headers; before indexing, it must allow

replace the parent's rules or sitemap with this application's scoped metadata.
