# References

References define qualities to study, not layouts to copy.

## 1. Reference Philosophy

For every reference, ask:
- What specific behavior or visual principle is useful?
- Why is it useful for Omnix?
- What must not be copied?

The final interface should be recognizable as Omnix.

## 2. Product References

### Linear
Study:
- information hierarchy;
- disciplined spacing;
- typography;
- quiet surfaces;
- product confidence.

Do not copy:
- purple glow language;
- exact section composition;
- logo/wordmark treatment.

### Vercel
Study:
- developer-first clarity;
- code/terminal presentation;
- sharp typography;
- limited decorative palette.

Do not copy:
- black/white brand identity wholesale;
- triangle motifs;
- exact button/component styling.

### Stripe
Study:
- complex concepts explained progressively;
- editorial pacing;
- technical content made approachable;
- strong documentation transition.

Do not copy:
- gradients;
- illustration language;
- signature Stripe layout patterns.

### Raycast
Study:
- product personality;
- polished developer-product motion;
- command-oriented storytelling.

Do not copy:
- red/purple visual branding;
- floating-window compositions.

### GitHub CLI / developer-tool sites
Study:
- installation clarity;
- platform expectations;
- source trust;
- command examples.

Do not copy:
- documentation-heavy visual density for the marketing hero.

### Warp / terminal products
Study:
- credible terminal rendering;
- mono typography;
- command hierarchy.

Do not copy:
- fake terminal interactions that imply capabilities Omnix does not have.

## 3. Interaction Reference — Game-level progression

The requested “Angry Birds” influence is conceptual:

- a clear starting point;
- a journey with sequential stages;
- progression that is visually obvious;
- anticipation of the next stage;
- milestones;
- a sense of motion through a system.

Do not use:
- Angry Birds characters;
- artwork;
- sounds;
- level graphics;
- slingshot imagery;
- copyrighted assets;
- a playful cartoon visual identity.

For Omnix, translate the pattern into:
**goal → orchestrator → context → specialist → validated output → future team**

## 4. Visual Keywords

Use:

- state
- precision

Avoid:
- cyberpunk
- neon hacker

- glowing brain
- robot mascot
- glass-card wall
- excessive 3D

## 5. Originality Check

Before approving a section, ask:

1. Could this section appear unchanged on any AI startup website?
2. Is the visual tied to a real Omnix concept?
3. Is the layout driven by content hierarchy?
4. If the gradient and animation disappeared, would the design still be strong?
5. Is this directly imitating one reference?

A “yes” to 1 or 5 requires redesign.
